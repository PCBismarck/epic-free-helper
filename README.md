# Epic 周免领取助手

面向 Windows Chrome / Edge 的 Epic 周免领取扩展，支持一键领取、已拥有游戏跳过和每日定时检查。

在浏览器中登录 Epic，安装扩展后即可使用。当前版本为 **1.1.0**。

## 功能

- **检查本周免费游戏**：从 Epic 官方促销接口获取当前有效的 PC 周免游戏。
- **自动领取**：按结账页语言核对官方商品名称，核验商品身份和零元价格后完成领取，并重新打开商品页确认入库。
- **跳过已拥有游戏**：确认商品页显示“已在库中”后，继续检查下一款。
- **继续暂停任务**：完成验证或登录后，点击“继续任务”，沿用保留页面和进度，完成后处理剩余游戏。
- **每日定时检查**：可开启每天北京时间 23:35 自动运行。
- **工具栏角标**：红色 `!` 提示失败或待处理，绿色 `✓` 表示最近一轮全部确认在库，蓝色 `…` 表示运行中。
- **进度与结果展示**：在扩展弹窗中查看每款游戏的状态，随时停止任务。

## 安装

1. 下载并解压本仓库源码，保留解压后的目录。
2. 在 Chrome 打开 `chrome://extensions`，或在 Edge 打开 `edge://extensions`。
3. 开启“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择仓库中的 `browser-extension` 目录，其中应直接包含 `manifest.json`。
5. 在同一浏览器中登录 Epic，点击扩展图标，再点击“领取本周游戏”。

更新扩展文件后，在扩展管理页点击“重新加载”。

## 使用说明

定时检查默认关闭。本轮全部游戏确认已领取或已拥有后，即可在弹窗中开启定时。浏览器需要保持运行；关闭浏览器或电脑休眠时，任务无法按时执行。

商品页就绪、结账页加载和提交后等待入库分别最多等待 60 秒。提交后的计时重新开始，结账加载较慢不会挤占这一窗口。出现拥有状态后，重新打开商品页核实入库，最多再等待 60 秒；官方促销接口单次请求超时为 15 秒。网络较差、浏览器后台加载延迟或页面状态始终无法确认时，任务可能暂停，需要检查后重新运行。

提交后仍持续检查结账子页面的安全验证，在提交后的 60 秒窗口内等待验证结果，不会重复提交订单。短暂出现后自行消失的验证窗口不会立即中断任务；如果页面要求人工验证，请只完成验证，后续入库检查由扩展继续。验证消失本身不代表领取成功，仍须确认游戏已在库中。

等待结账、验证或入库超时时，保留原页面并显示红色 `!`，不会刷新掉可能存在的验证或错误。弹窗和工具栏悬停提示会显示打开结账、提交订单、等待验证、确认入库等阶段。

每轮使用一个领取标签页，依次检查最多 10 款游戏。每次开始或继续最多运行 5 分钟；达到上限，或遇到需要登录、人工验证或无法识别的页面时，任务暂停并关闭定时，保留标签页供处理。

有可继续的暂停任务时，弹窗会显示 **“继续任务”**。处理完保留页面上的验证或登录后，直接点击它即可：已完成的游戏保留结果；当前游戏若已尝试提交订单，只检查入库，不再次获取或提交；若尚未提交，则继续核验原结账页。完成当前游戏后，自动处理剩余游戏。继续任务不会自动打开定时检查。

请保留原领取标签页。关闭浏览器、重新加载扩展、手动停止或关闭领取页后，可能无法继续旧任务，需要重新运行。旧版没有保存领取阶段的任务也需要重新开始。如果想放弃当前订单并重新试领，先点“停止本次任务”。

将扩展固定到工具栏后，可以直接查看图标角标：

| 角标 | 含义 |
| --- | --- |
| 红色 `!` | 领取失败、需要登录/验证、任务中断，或结果不完整；点击扩展查看具体原因。 |
| 绿色 `✓` | 最近一轮全部游戏已确认领取或已拥有。 |
| 蓝色 `…` | 正在检查或领取，尚未结束。 |
| 黄色 `–` | 手动停止，或本轮没有符合条件的周免游戏。已有失败记录时仍保持红色。 |
| 无角标 | 尚未运行。 |

鼠标悬停可查看最近检查时间、失败原因和定时是否开启。打开弹窗不会消除红色提示；重新运行时显示蓝色，全部成功后才显示绿色。浏览器或扩展重启后会按保存的状态恢复角标。角标表示最近一轮结果，不代表新一周已领取。角标使用浏览器内置 [Action API](https://developer.chrome.com/docs/extensions/reference/api/action)，无需新增权限。

## 隐私与权限

登录由 Epic 网站处理，扩展使用浏览器当前的登录状态，不收集密码或导出 Cookie。设置、任务进度和游戏结果保存在浏览器的扩展本地存储中。

扩展使用 Chrome Manifest V3，申请 `alarms`、`storage`、`scripting`、`webNavigation` 权限，页面访问范围限定为 Epic 域名。

## 开发与测试

开发环境需要 Node.js 22 或更新版本。在仓库根目录执行：

```sh
npm ci --ignore-scripts
npm test
```

测试包含 170 项领取逻辑及 DOM 检查、29 项后台生命周期及角标检查，使用模拟数据验证零价筛选、入库确认、已拥有跳过、慢速结账、提交后验证与短暂验证窗口、超时现场保留、继续任务、任务取消和调度行为。

另提供可选的离线 Chromium 检查，运行完整的弹窗、后台和页面流程，验证首款延迟 45 秒显示拥有状态时，两款已拥有游戏仍依次跳过，且获取与提交点击均为零；同时检查蓝色运行角标、绿色成功角标、促销接口失败后的红色角标，以及重新打开弹窗后提示仍然保留。脚本使用独立的临时浏览器目录以及本地页面、促销数据。

该检查需要 Linux 的 systemd 用户服务和 cgroup v2，并在启动前核验资源限制。在仓库根目录执行：

```sh
npx --no-install patchright install chromium
systemd-run --user --unit=epic-owned-skip-check --collect --wait --pipe \
  -p MemoryMax=2G -p MemorySwapMax=0 -p TasksMax=256 \
  -p CPUQuota=150% -p RuntimeMaxSec=75 \
  --working-directory="$PWD" node "$PWD/scripts/check-owned-skip.mjs"
```

临时数据和测试报告保存在 `.local/`，已由 `.gitignore` 排除。

另一个离线浏览器检查覆盖“已完成首款 → 第二款提交后验证超时 → 重新打开弹窗 → 继续原任务 → 处理第三款”。它使用本地模拟验证窗口，并将隔离测试工作线程的时钟前移 65 秒触发超时；确认复用原标签、已完成游戏不再访问、每款新游戏各点击一次获取和提交，以及最终显示绿色角标。运行方式：

```sh
systemd-run --user --unit=epic-resume-check --collect --wait --pipe \
  -p MemoryMax=2G -p MemorySwapMax=0 -p TasksMax=256 \
  -p CPUQuota=150% -p RuntimeMaxSec=75 \
  --working-directory="$PWD" node "$PWD/scripts/check-resume.mjs"
```
